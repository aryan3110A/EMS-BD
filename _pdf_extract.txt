2. MAJOR ARCHITECTURAL CHANGE –
PRODUCTION AND FULFILMENT MUST
BE SEPARATE
The most important change is that Container Fulfilment should no longer happen inside the
Production Run.
The revised flow should be:
Raw Material Inventory → Production Run → Production Finalisation → Processed
Inventory → Fulfilment → Sampling if applicable → Ready for Dispatch
Therefore:
Production Run is responsible for:
● Selecting input material
● Selecting process
● Processing material
● Entering wastage
● Deciding which wastage is stored/discarded
● Calculating final processed output
● Moving the final good output into Processed Inventory
Fulfilment is responsible for:
● Selecting available processed product
● Showing only contracts requiring that product
● Allocating processed inventory to contracts/containers
● Updating pending quantities
● Sending applicable containers to Sampling
Production Run must no longer directly allocate material to contracts or containers.
This separation is required throughout the application.

42. JOB WORK MODULE – OVERVIEW
A completely new Job Work workflow is required.
Job Work means material is sent outside the company’s plant for processing and later returned.
There may be:
● Multiple outward shipments
● Multiple inward/return receipts
● Additional material sent after processing begins
● Partial processed material returned
● Wastage returned separately
● Certain wastage discarded by the Job Worker
Therefore, every Job Work operation must have a unique Job Work Number.

JW-YYYY-00001

74. FINAL DEVELOPMENT PRINCIPLE
The revised system should be built around one central principle:
Every kilogram of material should always have a clear
state, location and history.
At any point, the system should be able to answer:
What product is it?
How many KG are there?
Where is it?
Is it Raw, WIP, Processed, Wastage or Sampling-Rejected?
If Wastage, which Wastage Type is it?
Which Production or Job Work did it come from?
Has it been reprocessed before?
Is it available or already reserved?
Has it been sent outside for Job Work?
Has it returned?
Has it been allocated to a Contract?
Does that Contract require Sampling?
The UI should keep this complexity hidden wherever possible and provide the Production Team
with simple actions, while the backend maintains complete stock traceability.
The intended result is a system where the Production Team can operate it without confusion,
while the Owner receives a highly visual, accurate and detailed picture of inventory,
production, wastage, fulfilment, sampling and Job Work at any given time.
